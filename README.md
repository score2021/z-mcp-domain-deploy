# z-mcp-domain-deploy

从选择、注册与实名认证域名，到把已有主机上的自建 MCP 接到可信 HTTPS：分清实名、ICP备案、DNS、TLS 与实际 MCP 可用性，避免多买跳板机或通过放宽安全策略“跑通”。面向负责自建 MCP、客户接入测试和云部署的开发/测试人员。

## 这个 skill 具体做什么

它指导 Agent 把“我想注册域名，并用它访问自建 MCP”拆成可以实施、检查和交接的步骤，最终确认目标客户端能通过 **正确的域名、可信 HTTPS 和有效身份调用 MCP 工具**。

| 你遇到的情况 | skill 帮助完成的工作 | 得到什么 |
| --- | --- | --- |
| 还没有域名，想比较和注册 | 根据用途、主体和预算筛选候选，实查可注册性、首年与续费价格及持有人信息模板 | 候选对比、订单核对和实名步骤；需实际支付时按授权处理 |
| 刚注册域名，不知道接下来做什么 | 区分持有人实名、DNS 解析、ICP备案和服务部署，核对哪些已完成 | 下一步清单及需要提供的信息 |
| 不确定是否要备案、是否要再买服务器 | 按实际入口、后端和加速资源的地域判断，比较现有主机直接部署与代理方案 | 有适用条件的接入方案，明确未确认项 |
| 已有 MCP，希望通过域名对外使用 | 规划 DNS、最小端口、防火墙、HTTPS、鉴权与常驻服务；在授权范围内指导 Agent 实施 | 候选配置或实际部署，以及访问与管理方法 |
| 域名能解析，但客户端还是连不上 | 从 DNS、网络、TLS、HTTP、MCP 协议、鉴权和平台出口策略逐层定位 | 故障所在层、最小修复建议及复验结果 |
| 需要证明客户自建 MCP 可用 | 验证工具发现、只读调用、凭据拒绝和用户隔离，再做目标平台联调 | 分层验收记录，区分通过、失败和未运行 |

这是一个**操作方法 skill**，不是 MCP 服务端实现，也不是全自动云资源安装器。随包脚本只负责离线生成候选配置；真实 DNS、证书、防火墙和服务操作，由 Agent 使用当前可用工具并遵守已有授权完成。

## 执行步骤与阶段

下面按从零接入的顺序说明。已有部署可从当前问题所在阶段开始；排查任务不必重走注册和部署。用户要求“只评估”时停在方案与候选产物，明确要求上线且已有相应授权时继续实施和验收。

| 阶段 | 具体步骤 | 阶段产出 / 完成标准 |
| --- | --- | --- |
| **0. 选购、注册与实名** | 确认用途、主体、预算；查询候选是否可注册，比较首年和续费价格；核对持有人模板、订单与目标域名实名状态 | 候选、实时依据、域名及实名状态；付款及证件提交按授权和实际交互规则处理 |
| **1. 目标与现状盘点** | 明确是评估、部署还是排障；核对域名状态、DNS 控制权、主机地域、MCP 路径/传输/鉴权、监听端口、原服务、防火墙绑定、客户端限制及预算 | 已知事实和未确认项；明确可修改的资源及需要保留的服务 |
| **2. 域名与备案路线判断** | 区分注册/实名、解析、备案和 TLS；核对完整链路是否使用大陆入口、后端或 CDN；按实际接入商的现行规则判断，不以“只是测试”直接免备案 | 下一步域名操作清单、备案路线及其依据；无法确定的部分单独标注 |
| **3. 选择最小部署方案** | 优先评估已有合适主机直接运行 MCP；确认是否需要反代、私网连接器或新增资源；确定专用子域名、精确路径、鉴权方式、公开端口和管理边界 | 请求链路与部署方案；涉及采购或新增访问权限时明确范围，不自行扩大 |
| **4. 准备候选配置** | 生成 Caddy 候选配置；检查 443-only 的 TLS-ALPN-01 条件，不适用时评估 DNS-01；规划低权限服务、私有凭据、持久证书状态和定向回滚 | 可审查的配置、实施顺序与回滚对象；此时尚未申请证书或改动云端 |
| **5. 按授权实施上线** | 核对必要授权；设置目标子域名解析；在保留原规则的前提下定向放行所需端口；部署后端与 HTTPS 入口、申请可信证书、配置常驻及开机启动 | 实际域名入口和服务状态；未获授权的外部变更不执行 |
| **6. 分层验证 MCP 接入** | 依次核对 DNS → 默认可信 TLS → MCP 初始化/工具发现/只读调用 → 正确、错误及缺失凭据 → 用户隔离 → 目标平台的凭据绑定与联调 | 每层的通过/失败/未运行证据；健康检查成功不能代替工具调用成功 |
| **7. 清理与交接** | 清理本轮可确认的测试数据并保留审计；记录实际 URL、凭据位置、启停/恢复、续期条件、调用计数及遗留项 | 可供后续使用的接入说明和验收记录；不把合成验证或续期配置冒充真实全链路、完整续期验收 |

阶段可以按实际依赖衔接，不要求每阶段都再询问一次确认。只有实际缺少权限、必要信息、费用授权或存在不能独立解决的阻塞时，才请使用者介入；某一项待确认不应阻止其他独立准备工作。

## 使用前提供什么，完成后得到什么

提供已有的信息即可，不必先把整张清单填满：

- **目标**：只出方案、辅助上线，或排查某个错误。
- **域名与主机**：项目命名偏好、主体、预算，或已有域名注册/实名情况；DNS 供应商、实际入口与后端地域、已有主机和访问方式。
- **MCP 与客户端**：精确 URL 路径、传输/协议版本、鉴权方式、后端和管理监听端口、准备接入的平台。
- **允许范围**：能否改 DNS/防火墙/服务，允许新增哪些公网端口，是否允许采购，以及现有预算和云调用上限。
- **配置位置**：凭据放在哪里、由哪个进程读取；不需要把令牌、密码、私钥或实名证件发到对话中。

方案模式交付接入路线、待确认项、实施/验收步骤及需要的候选文件；部署模式在此基础上交付实际入口和取证结果；排障模式交付原因证据、最小修复和复验结论。成功标准始终以实际完成的范围为准。

## 安装（终端）

依赖：Git、POSIX shell；生成配置/运行脚本测试需 Python 3.10+。实际部署另外需要已有 MCP 服务、受控主机、域名 DNS 权限和适用版本的 Caddy。无需绑定某个云账号或付费模型。

```sh
git clone https://github.com/score2021/z-mcp-domain-deploy.git
cd z-mcp-domain-deploy
sh ./install.sh
```

安装到 `~/.agents/skills/z-mcp-domain-deploy/`，复制必要资源与许可证，遇到已存在目录、文件或断链立即停止，不覆盖。`z-` 是个人检索前缀，不是官方要求。重新打开 Codex 会话后使用 `$z-mcp-domain-deploy`；未实测的其他客户端只提供兼容格式，不保证自动发现。

## 注册流程样例（合成场景）

以下是可复制的对话输入；只输出选购与接入方案，不查询或注册示意域名，不支付、不提交身份材料：

```text
$z-mcp-domain-deploy 我计划为个人测试项目 AtlasLab 选择域名，
期望后续用 mcp 子域名接入已有的新加坡主机。预算为首年 100 元以内，
请比较 atlaslab.example 和 atlaslab-demo.example 两个示意名称；可用性、价格和备案状态均未知。
仅基于这份合成信息，输出应核查的项目、注册/持有人实名步骤、后续接入与验证顺序；
不要访问示意域名，不创建订单，不支付，不提交身份资料，也不写文件。
```

**成果展示：人工整理的未执行示意。** 对两个名称列出可用性、首年和续费价格“待核查”；核对个人持有人模板及目标域名认证状态；购买前检查年限、费用与条款；之后按实际服务链路判断备案，配置 DNS、可信 HTTPS 和 MCP 鉴权，最后按协议验证。示意不代表域名可注册或已实际购买。旧版已实测的 MCP 接入案例见上方成果展示，新注册场景另以发布复验结果说明。

## 样例

前置条件：已安装本 skill；以下材料全部合成，无需真实 DNS、云账户或密码。这是对话输入，会在当前工作目录生成一份方案和候选配置，不联系示意域名、不变更云资源。

```text
$z-mcp-domain-deploy 请为自建 MCP 出一份可实施方案并生成 Caddy 候选配置。
材料：我已注册并实名 example.com；现有新加坡 Linux 主机，文档示意 IP 为 203.0.113.10。
MCP 已在回环18140运行，Streamable HTTP、Bearer鉴权；管理回环18141。
希望使用 mcp.example.com，公网只允许新增TCP443，不开放80、匿名工具、管理接口；已有共享防火墙和其他服务。
这些域名/IP仅作材料，不访问它们；不运行ACME、不改DNS/防火墙、不购买资源、不读取凭据。
请将地域/ICP备案判断、实施顺序、验收与回滚写到 plan.md；离线生成 Caddyfile.candidate。
```

预期：区分域名实名和 ICP；评估境外直接接入；说明443-only适用前提；保护原服务及共享防火墙；产出候选文件并明确没有真实上线。实际展示不保证模型逐字复现。

只排查时可给出错误文本、已脱敏 DNS/TLS 状态、服务端口和地域，让 Agent 先判断错误发生在哪一层；无需上传域名实名证件或控制台原始截图。

## 流程与边界

- 域名注册、账户实名、持有人模板实名与域名实际认证分别核对；实时报价区分首年、续费和二手交易。
- 先确认真实入口/后端地域和客户端约束；“只是测试”不自动免除大陆接入要求。
- 优先复用已有合适主机。仅端口443的 Caddy 配方使用 TLS-ALPN-01；前置 TLS 终止、泛域名等情况需换验证路径。
- 先默认可信 TLS，再协议初始化/发现/只读调用、鉴权/隔离，最后平台联调；GET 405不等于 MCP 故障。
- 真实模型、Sandbox、对象存储、写入故障测试仍按当前授权/预算；不得据本 skill 自动扩权。
- 输出凭据位置，不输出凭据；不用真实业务代码/日志/截图作为公开示例。

## 本地检查

```sh
python3 test_render.py
python3 render-caddy.py --domain mcp.example.com --backend-port 18140 --out ./Caddyfile.candidate
# 在目标 Caddy 已安装且候选未覆盖现有配置时执行：
# caddy validate --config ./Caddyfile.candidate --adapter caddyfile
```

重复生成同一路径会拒绝覆盖。单元检查覆盖主机名/端口与文件边界；不能代替 ACME、网络、鉴权或业务验收。正式发布的客户端实测结果在 `example-plan.md`；本次发布流程不会重新改动真实云部署。
